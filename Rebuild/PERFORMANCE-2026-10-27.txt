FREE PARKING 0.5.2 — DIRECT NATIVE INSPECTION
2026-10-27, build 2026102706

The installed production build now reads process identities, arguments, working
folders, open files and listening sockets directly through libproc/sysctl. A
small read-only C library is built with the macOS SDK and bundled with source.
No ps or lsof processes are started for these reads. Inaccessible processes are
retained or reported as errors; fresh PID/TTY/endpoint revalidation still runs.

One standalone iTerm API companion keeps a connection throughout each operation.
Inventory requests run concurrently inside a read transaction. Exact-target
closing and reordering use transactions; asynchronous window creation releases
the transaction first, to avoid deadlocking iTerm's window setup. Creation
receipts are captured before presentation updates, and lost replies are never
replayed. Window creation is addressed by the checked UUID, not frontmost focus.
The private companion is stopped after the operation instead of waiting for the
SDK's websocket shutdown timeout. This does not terminate iTerm or an agent.

The Python API must be enabled in iTerm Settings > General > Magic. Initial API
authentication still uses the SDK's Automation handshake. A single compatibility
inventory maps incomplete older saves' numeric IDs to exact native session groups.
Legacy coordinates are converted using the main screen's height. Existing saved
permissions, durable intents, receipt verification and all-window scope remain.
The Swift app still has one recovery worker per operation; executable preflight
uses the login shell. This removes repeated inspection subprocesses, not every
process boundary in the application.

Measured on the user's desktop
------------------------------
- All 3 windows / 12 tabs: about 0.07 seconds per warm full identity scan; the
  first scan including API connection setup took 0.37 seconds. All 12 resolved.
- Installed app helper, 2 tabs: 6.60 seconds park / 2.32 seconds fully restored,
  compared with 9.23 / 5.56 seconds in 0.5.1. Graceful agent exit dominates park.
- Installed app helper, 7 historical Backtrace tabs: 6.96 seconds park / 11.62
  seconds fully restored, compared with 14.26 / 15.26 seconds in 0.5.1.
  First tab creation was acknowledged at 0.67 seconds, last at 10.22 seconds.
  Every exact conversation, original order and streamed count 0 through 7 was
  verified; other working windows and their terminal IDs were unchanged.
- An earlier seven-tab run took 8.75 / 11.11 seconds including the subsequently
  removed two-second shutdown wait. Startup variability means that subtracting
  two seconds from that measurement is not a measured final restore result.
- An isolated native create took 0.16 seconds; exact native close took 0.02.
- 341 backend tests, 171 outer/legacy tests, Swift UI/bridge contracts and JXA
  boundary tests passed. New tests cover real kernel reads against an owned
  child, stale endpoints, exact native targets, legacy IDs, missing receipts,
  presentation failures, and creation outside the iTerm transaction.

The remaining restore delay is real: each agent must start before the next
append passes the existing conversation-identity guards. The final seven-tab
trace spent 10.30 seconds inside settling checks, including 6.62 seconds of
polling waits. Removing process-spawn overhead alone does not make that startup
sequence instantaneous. These are individual runs, not latency guarantees.

The installed app is /Applications/Free Parking.app, version 0.5.2. Raw timings,
session identities and acceptance outputs remain private and untracked.

PREVIOUS 0.5.1 LATENCY INVESTIGATION (historical)
2026-10-27, build 2026102705

Measured causes
---------------
An inventory of 3 windows / 12 tabs took 2.24 seconds and launched 62
subprocesses. Endpoint validation repeated a complete process inventory for
each Codex tab, then repeated it again at the end of the same observation.
Working-folder, open-file and socket reads also launched separate lsof helpers.

On the same desktop, parking the dedicated two-tab Claude/Codex fixture took
16.30 seconds: 8 observations and 451 subprocesses. Restoring it took 12.68
seconds: 6 observations and 335 subprocesses. These are measured native tests,
not the time taken to draw an animation or a fake workflow benchmark.

The UI independently limited a page to two cars. A third saved window was on
the next page, not missing from recovery. It also waited for the final helper
response before showing new cars, updating tab counts or animating departure.

Backtrace reads a cached session index and submits a launch command. It does
not establish the current owner of every live terminal, close a desktop, or
wait for every reopened conversation to verify. Its fast list and launch UI
are relevant design examples, but launch submission is not verified recovery.
Free Parking was doing far too much repeated process work regardless.

Changes
-------
Process file/folder/socket data is batched within one read-only observation.
No cached evidence crosses a mutation boundary. A separate fresh socket and
process read still verifies endpoint ownership, PID birth, TTY and candidate
process changes before the snapshot is returned. Normal direct identity checks
outside an observation retain their original immediate revalidation.

Mutation guards omit display-only name/title/bounds reads. iTerm topology and
receipts, conversation identity, folders, processes, duplicate checks, durable
recovery and final order checks remain. Native archive and client-shutdown
callbacks perform the fresh check immediately before sending instead of also
repeating the entire check before entering the provider's read-only preflight.
A failed pre-send check is explicitly NotSubmitted and remains retryable;
uncertain submitted operations still cannot be replayed.

A refresh now uses one read-only inventory for all recovery records and streams
existing saved cars before inspecting iTerm. It never uses that shared snapshot
to authorize a write. A scrolling grid exposes all saved windows (three columns
at the normal window width). Car departure starts on the opening click; actual
recovery stays present until verification, and incomplete returns keep the car.
Per-car progress and opened-tab counts arrive while the helper is still running.

Evidence and limits
-------------------
- Batched 12-tab inventory: 0.99 seconds / 11 subprocesses, all 12 identified.
- Final two-tab native test: 9.23 seconds to park / 5.56 seconds to restore.
  Counts fell from 451 to 75 subprocesses for parking and 335 to 55 for restore.
  Exact session identity, order and other working windows were checked.
- Final release helper, historical seven-tab Backtrace fixture: 14.26 seconds
  to park / 15.26 seconds to restore. All seven exact sessions and their order
  verified; the other working windows were unchanged. Streamed counts covered
  every value from zero through seven, before the final response.
- 326 backend tests, 171 outer/legacy tests, Swift UI/bridge contracts and JXA
  boundary tests passed. Tests include fresh endpoint/PID changes, late source
  reappearance, partial restore retry, early streaming and multiple saved cars.
- Native SwiftUI export shows all three cars together. Screen capture permission
  was unavailable; this is an own-view render, not a claim of automated UI clicks.

These are individual measured runs, not timing guarantees or percentile data.
The seven-tab flow is still a noticeable wait. Remaining costs include repeated
fresh AppleEvent inventories, CLI startup, graceful process exit, and verification.
One final two-tab run spent 3.59 seconds waiting for its agent client to exit.
The earlier functional acceptance should not have implied performance acceptance.

Logs
----
Each installed helper operation writes a private timing-*.jsonl file under
~/Library/Application Support/Free Parking/Diagnostics. Use Garage > Show
Performance Logs. Traces include nested durations, subprocess categories, native
RPC methods, observation counts, journal transitions and result/progress timing.
They omit command arguments, terminal contents, conversation text and titles.
Logs retain at most 30 files, with an 8 MiB per-operation cap; logging failure
cannot prevent recovery. Swift helper/progress timings also use the macOS log
subsystem com.jacobsapps.FreeParking, category performance.

Summarize the latest trace from a checkout with:
    python3 Rebuild/inspect_timings.py
Or pass one trace file. Inclusive spans overlap; self time excludes children.
Raw timing traces and native acceptance artifacts remain private and untracked.
